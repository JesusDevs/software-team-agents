# User Story & Acceptance Criteria Guide

## User Story Format
```
As a [type of user],
I want to [perform some action]
So that [achieve some goal/benefit]
```

## Acceptance Criteria — Gherkin Format
```
Given [context/precondition]
When [action performed]
Then [expected outcome]
And [additional outcome]
But [exception/negative case]
```

## INVEST Criteria
A good user story is:
- **Independent** — can be developed separately
- **Negotiable** — not a contract, open to discussion
- **Valuable** — delivers value to user or business
- **Estimable** — team can estimate effort
- **Small** — fits in one sprint
- **Testable** — clear acceptance criteria

## Story Points Scale
- 1 pt: Trivial change (1-2 hours)
- 2 pt: Simple (half day)
- 3 pt: Medium (1 day)
- 5 pt: Complex (2-3 days)
- 8 pt: Very complex (1 week)
- 13 pt: Epic — break it down

## Definition of Done
- [ ] Code written and reviewed
- [ ] Unit tests passing (>80% coverage)
- [ ] Integration tests passing
- [ ] Acceptance criteria verified
- [ ] Documentation updated
- [ ] Deployed to staging
- [ ] Product Owner accepted
